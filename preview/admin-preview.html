快速上手

  1. 在「渠道管理」添加上游渠道：OpenAI 兼容（OpenAI / DeepSeek / Moonshot 等）或 Anthropic 原生（Base URL 填 https://api.anthropic.com）。Base URL 末尾不要带 /v1，网关会自动拼接路径。
  2. 点击渠道行的「测试」验证连通性，确认返回成功后再启用；也可用「全部测试」批量巡检。
  3. 在「密钥管理」生成网关密钥并分发给调用方（可设置配额、有效期、允许调用的模型）。
  4. 调用方按 OpenAI 兼容方式调用即可，Anthropic 渠道也无需改代码，网关自动翻译格式。

调用示例

POST /v1/chat/completions，请求头携带 Authorization: Bearer <网关密钥>，请求体与 OpenAI 完全一致，支持 stream: true 流式输出。密钥列表中的「调用示例」可一键生成 curl 命令。

路由与容错

  • 模型匹配：按请求的 model 匹配渠道的模型列表，* 表示匹配全部。
  • 优先级 + 权重：先按 priority（越小越优先）分组，组内按 weight 加权随机，实现灰度与负载分摊。
  • 多 Key：单个渠道的 API Key 支持英文逗号分隔多个，随机起点轮询，单个 Key 失败自动换下一个。
  • 重试：429 / 5xx / 网络异常会在同一 Key 上重试（次数可在「网关设置」调整）。
  • 模型映射：网关模型名 → 渠道真实模型名，例如对外叫 gpt-4o-mini，实际走 gpt-4o-mini-2024。

Anthropic 渠道注意事项

  • 仅支持 /v1/chat/completions；max_tokens 必需（取请求值，否则用渠道「默认 max_tokens」）。
  • temperature 会自动钳制到 0~1；system / developer 消息合并为 Anthropic 的 system。
  • 连续同角色消息会自动合并（Anthropic 要求角色交替），多条 tool 结果会合并为一条。

数据存储

全部数据存放于 Cloudflare R2：data/channels.json（渠道）、data/keys.json（密钥）、data/settings.json（设置）、data/stats/<日期>.json（按天统计）、logs/<日期>/（请求日志）。可在渠道页「导出」备份配置。

接口一览

  • GET /v1/models、POST /v1/chat/completions、POST /v1/completions、POST /v1/embeddings
  • GET /healthz 健康检查；GET / 网关状态
  • 管理接口均在 /api/admin/*，需请求头 X-Admin-Key
